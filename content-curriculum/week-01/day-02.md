# Day 2: 接続の3分類・接続点分析

## この日のゴール

「接続」を感覚でなく構造で捉え、自分の仕事がどこで切れているかを
可視化できるようになる。

## 午前: 接続の3分類（10:00-12:15）

開発者の仕事の接続は3つに分類できる。

1. **技術接続**: コード・ドキュメント・システム間の接続。
   ライブラリの境界、API の契約、リポジトリの履歴
2. **人間接続**: チーム・レビュアー・後任者との接続。
   PR の説明、コミットメッセージ、引き継ぎ資料
3. **価値接続**: ユーザー・ビジネスとの接続。
   なぜそのタスクが存在するか、誰の何を改善するか

### ワークショップ: 同じロジック、違う語彙

Day 1 で見た省略記法に、名前をつけ直す。

```js
// 10分後の自分は他人 — 名前と構造が読み手の代わりに語る
const totalActiveValue = (records) =>
  records
    .map((r) => r?.value ?? 0)
    .reduce((sum, v) => sum + v, 0);
```

処理内容は Day 1 の `f` と同一。変わったのは語彙と改行だけだが、
読み手が推論に使える手がかりが増えた。
**接続の品質は、受け手側の推論コストで測る。**

## 午後: 接続点マップ作成（13:00-15:00）

- 自分の直近1週間のタスクを3分類に振り分ける
- 各タスクの「接続先」（誰が・何が受け取るか）を明記する
- 接続先が書けないタスクを洗い出す — それが盲点

## 分析と弱点選定（15:15-16:15）

- 分類結果の偏りを見る（技術接続に偏りがちか、価値接続が空白か）
- 最も弱い接続を1つ選び、12週間の改善対象として宣言する

## 成果物（Day 2終了時）

1. 接続点マップ（タスク × 3分類 × 接続先の一覧）
2. 弱点レポート（偏りの分析と改善対象の宣言）
