# Day 2: 12週間の全体系 — 個人OSから組織OSへ

## この日のゴール

12週間を1枚の地図に置き直す。個々の技法は
すでに学んだ。今日は**全体構造**——何のために
この順で学んだのか——を確認する。

## 3つの Phase、3つの OS

```text
Phase 1（W1-4）  個人の思考OS構築
  自分の判断を可視化し、AIと協働する
Phase 2（W5-8）  チームの協働システム
  判断の様式を合わせ、並列で考え、統合する
Phase 3（W9-12） 組織への実装とスケール
  部門を超えて最適化し、仕組みを自己進化させる
```

順序には意味がある。**自分の判断が言語化できて
いない人に、様式を合わせることはできない**。
様式が揃っていないチームを、部門横断で動かす
ことはできない。各 Phase は前の Phase の
成果を前提にしている。

## 道具の系譜: 同じ道具が3層を貫く

12週間の道具は、層が変わっても同じ構造で
スケールしてきた。これがこのカリキュラムの
一貫性の正体である。

| 個人（W1-4） | チーム（W5-8） | 組織（W9-12） |
| --- | --- | --- |
| 判断ログ | 判断共有プロトコル | 3レベル意思決定 |
| 仮説形式 | 共通様式での提出 | L2 調整の様式 |
| 悪魔の代弁者 | 矛盾検出の3分類 | 部門間バイアス対策 |
| Before/After 記録 | 週次PDCA | 差異分析と棚卸し |
| 前提知識の見積もり | 共通前提シート | 概念マッピング |

スケールの仕方には2種類あった。

1. **そのまま大きくする**: 手順は変えずに
  対象を変える（W7-8 の並列思考→W10 の
   部門間並列思考）
2. **レイヤーを足す**: 個人の記録→チームの
   共有→組織の記憶（判断ログ→共有
   プロトコル→判断事例DB）

どちらでも**判断の中身の様式（仮証形式・
強度・粒度）は共通**のままだった。この共通様式
こそが、層をまたいで判断を受け渡せる理由である。

## 3層の役割分担

```text
個人OS: 判断を言語化し、根拠と予測を残す
チームOS: 様式を合わせ、並列と統合で質を上げる
組織OS: 価値の流れで最適化し、記憶と進化を保つ

← 個人は様式を守って参加する
← チームは個人の判断を比較可能にする
← 組織はチームの枠を超えた判断の境界を持つ
```

## TRACK 最終回: 12週を振り返る

Week 6 Day 2 の TRACK を、12週全体に
適用する（W8 D3 では Phase 2 に適用した）。

- **T（思考）**: 12週をどんな構造で学んだか。
  自分の地図はここにあるか
- **R（記録）**: 何を残したか。判断ログ・
  事例DB・設計書。記録が残っている範囲だけが
  「持っている」ものである
- **A（分析）**: 何が効いたか。自分の判断の
  どの面が変わったか（Before/After）
- **C（接続）**: 何とつながったか。人・部門・
  道具の接続。新しく生まれた様式
- **K（改善）**: 次に何を変えるか。
  カリキュラム後の最初の一歩（Day 3 で設計する）

## ワークショップ: 自分の地図と道具棚

1. 上の12週マップに自分の到達度を書き込む
   （使える/使えるが遅い/知っている/未習の4段階）
2. 道具の系譜から自分が実務で使った道具に
   印をつける。使っていない道具は「どういう
   場面なら使うか」を1行で書く
3. TRACK の5問に自分の言葉で答える
4. 自分の組織に当てはめてみる: 3層のうち、
   どの層が最も弱いか。その層から何を1つ
   導入するか
