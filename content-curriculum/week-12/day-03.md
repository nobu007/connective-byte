# Day 3: 12週総括と次の一歩 — 思考OS設計書 v2

## この日のゴール

12週の締め。散らばった成果を1つの設計書に
統合し、カリキュラムが終わった後も**自分の
ペースで回り続ける最小セット**を決める。

## 持ち越し課題の決着

Phase の区切りでは、それぞれ課題を1件ずつ
持ち越してきた。

- Phase 1（W4）: チームで擦り合わせたい判断基準
- Phase 2（W8）: 部門を超えて擦り合わせたい判断基準
- Phase 3（W10）: 部門間連携の基本設計1枚

この3つを見返して、現状を判定する。

```text
決着の判定:
- 解けた   → 判断事例DBに登録して完結
- 変わった → 課題を書き直して継続
- 手つかず → 障害を1行で書く
            （時間/権限/相手。書けないなら
             課題として大きすぎる）
```

解けたものは必ず事例DBに還元する。課題の
決着こそ、12週間の道具が「効いた」証拠の
取りやすい場所である。

## 継続運用の最小セット

全部の道具を回し続けるのは不可能であり、
不要である。**頻度を階層に分けた最小セット**に
絞る。

| 頻度 | 回すもの | 粒度 |
| --- | --- | --- |
| その都度 | 判断ログ | 概要のみ（可逆な判断） |
| 週次 | PDCA の Check だけ | 数行でよい |
| 月次 | 判断事例DBへの登録 | 重要判断1件以上 |
| 四半期 | result 埋め・差異分析・棚卸し | Day 1-3 の様式 |

それ以外の道具（QUEST・観点分解・創発の
操作など）は、**必要になったときに取り出す**
道具箱に入れておけばよい。毎日使う道具と、
引き出しの道具を分けることが、続く運用の
条件である。

```text
継続の条件:
1. 最小セットは1日あたり数分で済む量にする
2. 四半期の棚卸しは日付を先に予約する
3. 運用は様式で残す（人に依存させない）
```

## 思考OS設計書 v2

Week 4 Day 3 で「判断支援システム」設計1枚を
作った（判断ログ＋AI協働欄＋深掘り5段階＋
統合プロセス）。それを12週仕様に改訂する。

```yaml
# 思考OS設計書 v2（様式例）
thinking_os_v2:
  personal:        # 個人OS（W1-4 の改訂）
    judgment_log:  判断ログ（粒度3レベル）
    evidence:      強度階層1-5 での評価
    ai_collab:     任せる判断/持つ判断の境界
  team:            # チームOS（W5-8 の追加）
    protocol:      判断共有プロトコル（scope/
                    criteria/escalation/share）
    session:       判断セッション（QUEST）
    cases:         判断事例DB（result つき）
  org:             # 組織OS（W9-12 の追加）
    levels:        3レベル意思決定と移動条件
    flow:          価値の流れの評価軸
    evolution:     四半期の棚卸しと改善実験
  next:            # 次の一歩（1件だけ）
```

v1 との差分が、この12週間の成果である。
Week 1 からの Before/After 記録と突き合わせて、
自分の判断がどこで変わったかを確認して
ほしい——速さ・根拠の明示・記録の残し方・
他者との擦り合わせ方、どこが変わっていても
よい。

## 次の一歩

12週間は「学びの終わり」ではなく**運用の
始まり**である。次の一歩は大きくなくてよい。
候補を3つ挙げる。1つを選ぶこと。

1. **自分の判断を深める**: 判断事例DBを
   個人で回し続ける。四半期後に result 埋めで
   自分の予測精度と出会う
2. **チームに1つ導入する**: 最も軽い様式
  （粒度の揃え方、または判断ログの型）を
   1つだけ、期限つきの実験として（W11 D3 の
   改善実験の様式で）
3. **橋渡しを引き受ける**: 自分の部門と隣の
   部門の間で、概念マッピングを1枚作る
   （W9 D2 の翻訳の実践）

どれを選んでも、出発点は今日作る v2 である。

## ワークショップ: 設計書 v2 の完成

1. 持ち越し課題3件の決着判定を書く
2. 自分の継続運用の最小セットを確定する
  （表の頻度を自分の実情に合わせて調整し、
   四半期の日付を予約する）
3. 思考OS設計書 v2 を書き上げる
   （v1 からの差分が分かる形で）
4. 次の一歩を1つ選び、最初の行動と日付を
   書く

## 成果物（Day 3終了時 = 12週プログラム終了時）

1. 思考OS設計書 v2（3層＋次の一歩）
2. 継続運用の最小セット（四半期予約つき）
3. 12週間の総括（持ち越し課題の決着＋
   Before/After の最終比較）
